# AI 상태머신·경기 변주 검증 (v0.12.20)

## 문제
1. 서브를 받는 도중 세터가 공 길목(머리 높이 1.7m)에 서서 머리로 맞았다. 원인: 보조 위치가 "공의 z를 그대로 따라감"이었다.
2. 경기마다 같은 상황이 반복됐다. 원인: 모든 AI 값과 서브가 고정이라 120초 경기 12개의 초반 접촉이 모두 같았다.

## 구조
- `simulation/ai-brain.js`: `AiState`(is-a) → `ReadyState`·`CoverState`·`ReceiveState`, 접근형 `AttackState`·`SetState`·`ChaseState`. `Temperament`(has-a)가 반응 시간·간격·위치 흔들림을 가진다. `AiBrain`이 전이를 적용한다.
- 전이: 받기·공격·세트·추격은 즉시. 대기로 돌아가는 것도 즉시. 대기→보조만 선수 성향의 반응 시간(0.02~0.24초) 뒤.
- 보조(세터·공격수·리시버 모두): 공이 아직 지나가기 전이고 도착 지점이 우리 쪽이면 공 궤적에서 1.0~1.5m 이상 떨어진, 서 있던 쪽으로 비킨다. 쪽(lane)은 상태에 들어올 때 한 번 정해 좌우로 흔들리지 않는다.
- 성향은 `state.seed`·선수 번호·랠리 번호의 해시로 정한다(Math.random 없음). 서브 토스도 같은 시드로 ±(위치 0.03~0.08m, 속도 0.05~0.08m/s)만큼 변한다.
- 시드: 혼자 하는 경기는 `crypto.getRandomValues`, 온라인은 방 코드 해시(두 사람이 같은 값), 훈련은 고정.
- 값은 `config.ai.temperament`·`config.ai.serve`에 있다.

## 측정 (120초 × 24경기, 매 경기 다른 시작 틱/시드)
| 지표 | 이전(main) | 이번 |
|---|---:|---:|
| 머리 접촉 | 42 | 6 |
| 초반 14접촉 열의 종류(24경기 중) | 3 | 23 |
| 득점 수 | 324 | 305 |
| 평균 랠리(초) | 5.36 | 5.96 |
| 스파이크 | 234 | 289 |
| 아웃 | 84 | 90 |

원인 분리(같은 24경기): 서브 변주를 2배 폭(±0.16m·0.22m/s 등)으로 키우면 랠리 4.16초·아웃 120으로 나빠져 지금 값으로 줄였다. 성향·회피는 켠 채 서브 변주만 끄면 랠리 6.45초·스파이크 298이다.

남은 머리 접촉 6건은 대부분 받는 선수 본인이 높은 공(1.5m 이상)을 받다가 생긴 것이다. 이번 변경 범위(보조 위치)가 아니다.

## 테스트
`tests/ai-brain.spec.js`: 성향 결정론·범위, 전이 규칙(반응 시간·긴급 상태), 기록 검증, 같은 시드 동일/다른 시드 상이, 저장→복원 뒤 이어 진행한 결과가 끊김 없이 진행한 결과와 같음.

## 동기 시험 (v0.12.21, `tests/sync.spec.js`)
전송 계층(WebRTC)은 제외하고 시뮬레이션의 결정론과 스냅샷 완전성만 본다. 두 사람이 같은 방 코드(온라인 시드)로 틱 번호만으로 정해지는 이동·점프·발차기·눌림 입력을 넣는다.
| 시험 | 내용 | 결과 |
|---|---|---|
| 두 피어 | 3600틱, 300틱마다 전체 상태(`save()`) 지문 비교 | 일치 |
| 방 코드 다름 | 1500틱 뒤 상태 | 달라짐(변주 있음) |
| 롤백 | 1200틱에서 40틱 잘못 진행 → 1000틱 저장본 복원 → 재실행, 3600틱까지 비교 | 끊김 없는 진행과 일치 |
| 중도 합류 | 1400틱 저장본으로 새 피어 합류, 이후 1200틱 비교 | 일치 |
| 다시 시작 | 같은 틱의 명령으로 두 피어가 새 시드 선택 후 1100틱 비교 | 일치, 시드 바뀜 |
- 변이 확인: 롤백 복원을 물리만 되돌리도록 바꾸면 이 시험이 실패한다(상태·AI 기록 누락을 잡는다).
- 이 시험이 고친 문제: 다시 시작 명령이 항상 기본 시드(7)로 되돌아가 두 번째 경기부터 변주가 없었다. 현재 시드·랠리·틱에서 새 시드를 만든다.

## 미검증
- 실제 화면 E2E와 WebRTC 전송·지연·손실 상황의 동기는 이 환경에서 실행하지 못했다.
- 사람이 직접 받는 흐름에서 보조 위치가 자연스러운지는 플레이 확인이 필요하다.
