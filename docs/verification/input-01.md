# 입력 자유도 1단계 — 받기 보조 (v0.12.34)

## 문제
발차기를 누른 채 공의 착지점으로 그대로 달려가면, 선수가 공이 떨어질 자리 위에 서서 공이 발이 아닌 허벅지·몸통·머리에 맞는다. 받는 자리(발자국 표식, `stance`)는 착지점보다 0.8m 뒤인데, 달려가는 속도를 줄이는 입력은 사람이 따로 해야 했다.

## 변경
`TakrawGame.assistReceive`(`src/simulation/game.js`): 사람이 점프 없이 발차기를 누르고 받는 선수일 때, 착지 0.9초 전부터 받는 자리 쪽으로 가는 입력(자리 방향과 내적 0.35 초과)의 **크기만** 남은 거리×2.2로 줄인다. 방향·점프·발차기는 건드리지 않는다. 슬라이드, 훈련 모드, 입력이 거의 없을 때, 자리 반대로 가는 입력, 점프 중에는 돕지 않는다. 설정은 `ai.receive.assist`(SSOT). 상태를 저장하지 않고 현재 상태에서만 계산하므로 락스텝·롤백에 새 동기 상태가 없다. AI 선수에는 적용되지 않는다.

## 측정 (`scripts/scene-receive.mjs`, 각 144회)
상대 코트(x=0.8, 높이 3.0m)에서 네트를 넘어 오는 공을 사람이 받는 장면. 성공 = 발·종아리로 쳐서 1.2초 안에 최고 1.8m 이상, 네트를 넘지 않음. 거리 1~4m × 발차기 누르는 시점(착지 0.65/0.5/0.4초 전)의 합계.

| 사람 입력 방식 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 착지점으로 그대로 달려가며 발차기(toBall) | 13/144 | 24/144 |
| 받는 자리 표식을 따라 이동(guide) | 30/144 | 32/144 |

착지점으로 그대로 달려가는 입력이 약 1.8배가 되었고, 표식을 따라가는 입력은 줄지 않았다.

## 남은 것 (측정으로 확인한 사실)
- 발차기를 늦게 누를수록 급격히 나빠진다: toBall 기준 착지 0.65초 전 누르기 18/48, 0.5초 전 6/48, 0.4초 전 8/48. 발차기를 누른 뒤 발이 준비되는 시간이 필요해서로 보이나 원인은 확정하지 않았다.
- 발에 맞아도 최고 높이가 1.8m 미만인 약한 패스가 가장 큰 실패 종류(48회 중 약 16~20회)다. AI도 같은 장면에서 비슷하다(13/48 성공). 받는 발의 타격 제어 자체의 한계로 보이며 이 단계에서는 바꾸지 않았다.
- 이 환경은 브라우저가 CDN 없이 시작되지 않아 실제 화면의 조작감은 확인하지 못했다(미검증).
